Tècniques de tolerància

Aquestes són les operacions bàsiques que necessites per treballar amb toleràncies de manera correcta. La idea és tenir-les implementades un sol cop (idealment en un mòdul d'utilitats numèriques) i reutilitzar-les, en lloc de repartir epsilons màgics pel codi.

Calcular un ULP​

Donada la distància entre un valor i el següent float representable pots construir qualsevol tolerància: si esperes N ULPs d'error, la tolerància és N * ulp(x). Per a nombres normals, ulp(x) = epsilon * 2^floor(log2(|x|)).

Tolerància per cancel·lació​

Per a una operació on hi pot haver cancel·lació (una resta de termes similars), la tolerància es calcula a partir de l'escala dels operands, no del resultat:

tolerance = ulps * epsilon * scale

on scale és la magnitud dels termes (per exemple |a*d| + |b*c| en un determinant 2x2).

Quants ULPs? Com a guia orientativa, en funció de quantes operacions acumula el càlcul:

SituacióULPs aproximats
comparació general (~2 operacions)4
determinant (2 productes + 1 resta)8
classificació d'extrems paramètrics (t ≈ 0/1)8

Test de prop-de-zero​

"És aquest determinant zero?" → comprovar si el valor és petit respecte a l'escala del càlcul que l'ha produït, no respecte a un epsilon fix.

Test de near-igualtat​

L'enfocament general recomanat combina tres comprovacions:

  1. Igualtat exacta (gestiona +0 == -0, inf == inf).
  2. Diferència absoluta dins d'una tolerància absoluta (gestiona el cas a prop de zero).
  3. Diferència dins de N ULPs de la magnitud més gran (comparació relativa lluny de zero).

Recorda fixar una tolerància absoluta significativa quan els valors puguin ser a prop de zero.

Snapping​

Arrodonir un valor calculat a un valor exacte quan la diferència és dins de l'error esperat. Després d'un snap, les comparacions exactes tornen a ser vàlides:

// pseudocodi il·lustratiu
t = snap(t, /*target*/ 0.0f, /*scale*/ 1.0f, /*ulps*/ 8);
if (t == 0.0f) { /* ara la comparació exacta és fiable */ }

Determinant promocionat​

Per a un determinant 2x2 (a*d - b*c), promoure els inputs float a double abans de multiplicar redueix l'error dels productes (tot i que l'error de la resta segueix limitat per la precisió dels float originals). Convé obtenir també l'escala (|a*d| + |b*c|) per calcular la tolerància del test de prop-de-zero.

Nota sobre FMA

Aquestes toleràncies assumeixen aritmètica estàndard (no fusionada). Si el codi fa servir instruccions fused multiply-add (FMA), els productes intermedis no s'arrodoneixen abans de la resta i el perfil d'error canvia.
